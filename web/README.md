# Веб-интерфейс Scanner

Одностраничное приложение на React + TypeScript (Vite) поверх REST API сканера
(`scanner/api`). Всё взаимодействие идёт только через API: интерфейс не
сканирует сам и не обходит проверки — права (RBAC), allowlist договора и журнал
аудита применяются на сервере.

## Разделы

| Раздел | Кто видит (право) | Что внутри |
|---|---|---|
| Обзор | `view_report` | KPI последнего прогона, тренд открытых уязвимостей, распределение по опасности, последние прогоны, самые уязвимые хосты, приоритетные уязвимости с БДУ/CVE |
| Договоры и allowlist | `view_engagements`; правка — `manage_engagements`, `manage_allowlist` | Договоры, разрешённые диапазоны, история прогонов |
| Прогоны | `view_report`; запуск/остановка — `run_scan` | Запуск (цели, модули, профиль нагрузки, подтверждение объёма работ), мониторинг со статусом в реальном времени |
| Находки | `view_report` | Фильтры по опасности, модулю, статусу, БДУ, поиск по CVE/БДУ/хосту, группировка по хостам, карточка уязвимости со ссылками на БДУ ФСТЭК и NVD |
| Хосты | `view_report` | Сводка по каждому хосту: сервисы, все уязвимости, распределение |
| Отчёты | `view_report` | Просмотр HTML и выгрузка PDF / Word / HTML / JSON по любому завершённому прогону |
| Журнал аудита | `view_audit` | Фильтры по субъекту и действию, детали записи |
| Пользователи и роли | `manage_users` | Создание, роли, блокировка, сброс пароля |

Модуль **аудита учётных данных** показывается в форме запуска только при праве
`cred_audit`. Администратор по замыслу не запускает прогоны (разделение
обязанностей), поэтому кнопки запуска у него нет.

Тема — тёмная по умолчанию, переключается в меню (запоминается в браузере).

## Разработка

```bash
cd web
npm install
npm run dev            # http://localhost:5173, /api проксируется на http://localhost:8000
```

Адрес API для dev-прокси: `SCANNER_API_URL=http://host:8000 npm run dev`.
API должен быть запущен (`uvicorn scanner.api.main:app`) и иметь хотя бы одного
пользователя (`SCANNER_API_BOOTSTRAP_ADMIN` / `SCANNER_API_BOOTSTRAP_PASSWORD`).

Проверки:

```bash
npm run lint
npm run typecheck
npm test
npm run build          # статика в web/dist
```

## Сборка и запуск в контейнере

```bash
docker build -t scanner-web web/
docker run --rm -p 8080:8080 -e API_UPSTREAM=http://api:8000 scanner-web
```

Контейнер (nginx без root, порт 8080) раздаёт статику и проксирует `/api/*` на
`API_UPSTREAM`, так что интерфейс и API работают с одного origin. Заданы
заголовки безопасности (CSP, `X-Frame-Options: DENY`, `nosniff`,
`Referrer-Policy: no-referrer`). Проверка живости — `GET /healthz`.

Если интерфейс всё же нужно открыть с другого origin, разрешите его на стороне
API: `SCANNER_API_CORS_ORIGINS=https://scanner.example.local` (через запятую), а
при сборке укажите `VITE_API_BASE=https://api.example.local`. По умолчанию CORS
выключен.

## Безопасность на стороне клиента

* Токен доступа хранится в `sessionStorage` (живёт до закрытия вкладки), при
  ответе 401 сбрасывается и открывается страница входа.
* Отчёты скачиваются через `fetch` с заголовком `Authorization`; HTML-отчёт для
  просмотра открывается в `<iframe sandbox>` без скриптов и без доступа к
  origin интерфейса, потому что содержит данные со сканируемых хостов.
* Форма запуска требует подтвердить, что цели входят в объём работ по договору;
  окончательно цели проверяет API по allowlist.

## Структура

```
src/api/         клиент REST API и типы (зеркало scanner/api/schemas.py)
src/auth/        вход, текущий пользователь и права, текущий договор
src/components/  каркас, таблицы, формы, карточка уязвимости, графики
src/lib/         подписи, агрегаты (сводка, по хостам, фильтры), форматирование
src/pages/       экраны
```
