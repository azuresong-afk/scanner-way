# 6. Сведения о выпусках

## Следующая сборка (в разработке)

### Выгрузка находок и плана исправлений в Excel и CSV

В «Находки» → «Все находки» и «Что исправить», а также в карточке актива
появились кнопки «Выгрузить: Excel · CSV». Файл содержит всё, что подходит под
фильтры на экране, без деления на страницы: находки — с рекомендацией и
ссылками на устранение, план — с командами, проверкой и хостами (в Excel ещё
лист «По хостам» и лист «Сведения»). Сроков устранения в файлах нет. Значения
со сканируемых хостов не исполняются как формулы. Выгрузка пишется в журнал
аудита (действие `export`). Миграции нет. Проверка —
[TESTING.md, шаг 10д](../TESTING.md#шаг-10д-выгрузка-находок-и-плана-в-excel-и-csv-).

### Выход закрывает сеанс, вход продлевается

«Выйти» теперь отзывает сеанс на сервере: токен перестаёт действовать сразу, а
не через час. Пока пользователь работает, вход продлевается сам; отошёл —
за 5 минут до выхода появится «Продолжить работу». Предел сеанса — 12 часов
(`SCANNER_API_SESSION_MAX_HOURS`), потом снова пароль и код 2FA. Отключение
учётки, новый пароль и сброс 2FA закрывают все сеансы пользователя; в профиле —
список своих сеансов, у администратора — «Завершить все сеансы». Работает с
входом через AD и 2FA. API: `POST /auth/refresh`, `POST /auth/logout`,
`GET /me/sessions`, `DELETE /me/sessions/{id}`, `POST /me/sessions/revoke-others`,
`DELETE /users/{id}/sessions`. Миграция `0030` (`auth_sessions`). После
обновления все войдут заново один раз. Проверка — [TESTING.md, шаг 3](../TESTING.md#шаг-3-вход-и-безопасность-входа).

### Состояние сканера (хелсчек)

Новый раздел «Администрирование → Состояние»: по каждому компоненту сканера —
в порядке / требует внимания / не работает, и что сделать. Проверяются служба
API, база данных, фоновые службы, прогоны, движки (с версиями), справочники,
свободное место, связь с узлами-сканерами и доставка уведомлений. При проблеме
в шапке появляется плашка. Монитор раз в 5 минут сообщает о сбое и
восстановлении через новое событие уведомлений «Состояние сканера».
Для внешнего мониторинга — `/api/health/status` и команда `scanner health`;
у контейнера узла-сканера появился HEALTHCHECK (`scanner node health`).
Миграции нет. Проверка — [TESTING.md, шаг 13д](../TESTING.md#шаг-13д-состояние-сканера-хелсчек-).

### Вход через Active Directory и двухфакторный вход

По желанию заказчика, **по умолчанию выключены** — без новых переменных в
`.env` всё работает как раньше.

| Что | Как включить |
|---|---|
| Вход логином и паролем домена (LDAPS/STARTTLS), роли по группам AD, пересчёт ролей при каждом входе; учётки помечены «Домен» | `SCANNER_API_LDAP_*`, проверка — `scanner auth ldap-check` |
| Двухфакторный вход TOTP (Яндекс Ключ, Google Authenticator): по желанию пользователя или обязательно для всех, коды восстановления, сброс администратором | `SCANNER_API_MFA=optional` или `required` |

Миграция `0027`: `users.auth_source` (`local`/`ldap`/`platform` — последний
под вход через «Платформу»), DN каталога и поля 2FA. Проверка на стенде —
[TESTING.md, шаг 4б](../TESTING.md#шаг-4б-вход-через-ad-и-двухфакторный-вход-по-желанию-).

### Узлы-сканеры для изолированных сегментов (сетевой режим)

Прогон можно выполнить узлом-сканером внутри сегмента, куда центральный
сервер не дотягивается (филиал, ДМЗ, АСУ ТП). Узел — тот же образ без
веб-интерфейса и БД (`docker-compose.node.yml`, `.env.node`). Он сам выходит на
центр по HTTPS: на межсетевом экране нужно одно правило «узел → центр, TCP 443»,
входящих портов на узле нет.

| Что | Где |
|---|---|
| Раздел «Сканеры»: заведение узлов, токен один раз с готовым `.env.node`, статус, сети, инструменты, перевыпуск токена, отключение | право `manage_nodes` (администратор) |
| «Где выполнять» при запуске прогона и в расписании; узел в карточке и списке прогонов | оператор |
| Allowlist на трёх рубежах: проект ∩ сети узла в центре, локальный allowlist на узле (центр его не меняет), фильтр результата в центре | журнал аудита: `deny`, `node_result_filtered` |
| Справочники БДУ/NVD/MSRC и бюллетени ОС — у центра (только чтение), шаблоны Nuclei — от центра раз в сутки; результат при обрыве связи ждёт в очереди на узле | — |
| mTLS по желанию через HTTPS-прокси центра, отпечаток сертификата закрепляется за узлом | `SCANNER_NODE_MTLS_*`, `docs/examples/nginx-node-mtls.conf` |
| Узел пропал посреди прогона — «Прерван» с «Повторить»; прогон, который ждёт узел, не прерывается | — |

Миграция `0028`: таблица `scan_nodes`, `scan_runs.node_id`,
`scan_schedules.node_id`. Установка —
[INSTALL.md, раздел 13в](../INSTALL.md#13в-узлы-сканеры-в-изолированных-сегментах),
проверка на стенде — [TESTING.md, шаг 13в](../TESTING.md#шаг-13в-узлы-сканеры-прогон-из-изолированного-сегмента-).

**Автономные узлы** — для сегментов без связи с центром (АСУ ТП, закрытый
контур). «Выгрузить задание» на странице прогона → файл `.scnjob` на носителе →
`scanner node run-job` на узле → файл `.scnres` → «Загрузить результат».
Файлы подписаны (Ed25519) и зашифрованы (X25519 + AES-256-GCM); повтор,
подмена, чужой узел и истёкший срок (по умолчанию 14 дней + 3 дня на
загрузку) отклоняются. Узел сопоставляет находки со своей копией справочников
из `scanner bundle` и без них не запускается. Миграция `0029`: таблица
`offline_jobs`. Установка — [offline-node.md](../offline-node.md) и
[INSTALL.md, раздел 13г](../INSTALL.md#13г-автономный-узел-сканер-закрытый-сегмент),
проверка — [TESTING.md, шаг 13г](../TESTING.md#шаг-13г-автономный-узел-сканер-задание-и-результат-на-носителе-).

### Как обновиться

```bash
scripts/backup.sh && git pull && docker compose up -d --build
```

После обновления перенесите в свой `.env` новые параметры из `.env.example`
(значения по умолчанию рабочие): лимиты сетевого поиска
`SCANNER_API_PORTSCAN_*`, проверки учёток `SCANNER_API_CREDENTIAL_CHECK_*`,
предварительной проверки SSH `SCANNER_SSH_PREFLIGHT`, `SCANNER_SSH_ATTEMPTS`,
`SCANNER_SSH_RETRY_DELAY_SEC`, комплекта данных `SCANNER_BUNDLE_AUTOLOAD`,
`SCANNER_DATA_BUNDLE_URL`, сетевого оборудования `SCANNER_NETDEV_*`. Подробно — [Руководство администратора, 8.1](03-admin-guide.md#81-обновление).

## Как вести сведения о выпусках

Для каждой следующей версии добавляйте раздел сверху по той же схеме:
номер и дата, последняя миграция, «Как обновиться» (новые параметры `.env`,
ручные действия), новое по областям с номерами PR, переименования, миграции,
что требует проверки на стенде, изменения в ограничениях. Номер версии
меняйте в `pyproject.toml` и `scanner/api/main.py`.
